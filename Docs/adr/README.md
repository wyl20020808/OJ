# Architecture Decision Records

ADRs record architecture-significant decisions after review. They complement the [Architecture Baseline](../OJ_PROJECT_ARCHITECTURE_BASELINE_V1.md); an ADR must not silently weaken it.

## Statuses

`PROPOSED`, `ACCEPTED`, `SUPERSEDED`, `REJECTED`, and `DEPRECATED`.

## Naming

Use `NNNN-short-kebab-title.md`. Create an ADR when a real requirement changes an architecture-significant boundary; do not create speculative records merely to fill the directory.
